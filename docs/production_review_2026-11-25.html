Arquitectura y robustez del pipeline OOT

Revisión 2026-11-25. Inputs: panel configurado, scores OOT por entidad, modelos locales y estados de revisión del navegador. Created / Last modified: 2026-11-25.

Cambios

Política numérica de P99 con empates; conteos reconciliados entre detectores; validación de deriva de entrada; interpretación científica del fallback; protección de serialización y estado del analista; controles de complejidad y CI.

El Excel de control conserva P90+. La cola del dashboard utiliza P99 por detector. La concordancia entre IF y VAE apilado no demuestra independencia ni exactitud.

Stack y publicación

Python local, sklearn, PyTorch y Optuna; estudios SQLite locales; dashboard HTML estático; servidor de progreso en 127.0.0.1. No se verificó hosting cloud ni base transaccional de casos. GitHub publica el código y ejecuta CI. Los modelos y datos personales permanecen en artifacts/.

Evidencia y límites

El registro completo de comandos, rondas adversariales, alternativas, fuentes, inventario y pendientes está en el informe Markdown. La deuda de complejidad heredada se controla con un baseline decreciente; funciones nuevas requieren complejidad ≤10. La calidad predictiva requiere replay operativo con resultados revisados. La persistencia del navegador no sustituye un servicio multiusuario.

Referencias: NumPy, scikit-learn, MDN, Radon.
